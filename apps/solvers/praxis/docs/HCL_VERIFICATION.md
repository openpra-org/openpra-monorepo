# HCL numerical verification

Updated 2026-09-12 for task 42. Solver algorithms remain unchanged.

## Independent references

| Check | Reference and boundary |
| --- | --- |
| Scalar HCL | Main's `tests/hcl_equivalence.rs`: a deterministic unified BN and bounded full-state enumeration; the legacy `lazy_k5` also uses its frozen Python-generated unified XDSL. |
| Backend and addon | `workbook-analysis-runs.spec.ts` sends HTTP requests through real controllers, Praetor and the native addon, then checks saved results against `hcl-independent-oracle.ts`. The oracle reads original workbook snapshots, follows FT/ET transfers, and adds deterministic BN gates. It does not use the production FT/ET adapters, BDD or HCL traversal. |
| Small dependent ETs | Full-state enumeration checks overlapping subsets of a three-state BN, child-node evidence, repeated events, impossible paths and transfers. This path does not use TensorBayes. |
| Uncertainty | Frozen outputs generated by unchanged HCL_MH sampling, vectorized Shannon and summary functions. MC and LHS cases combine Beta/Dirichlet CPT priors with FT distributions, three evidence rows and 513 paired samples, crossing chunk boundaries. |
| Case study | Every sequence in the saved reconstructed LOOP/SBO/FLEX example: 55 + 36 + 13 paths, plus 55 paths under each of two LOOP evidence scenarios. Check 214 sequence probabilities, annual frequencies and end-state totals, as well as an FT top event. |
| BN inference | TensorBayes' inference/enumeration corpus checks hard/soft evidence, parent axes, multiple queries, batched CPTs and cache reuse. |

The backend UQ checks compare every exposed summary field for FT, sequence and
end-state results against HCL_MH, including transferred FTs. Rust source tests
also compare the underlying sampled vectors and sample pairing directly.

Unified BN queries share TensorBayes with HCL; they independently check the
BDD/HCL traversal and application adaptation, not the BN engine itself.
Full-state enumeration supplies a separate engine check for compact cases.
The reconstructed case study has provisional inputs; this verifies those saved
inputs, **not published dissertation numerical results**.

## Bug found by these checks

The backend built HCL event membership from direct FT leaves before expanding
FT transfers. BN links reached through a transfer could disappear, leaving the
solver to use independent event probabilities. Membership and contribution
records now use the flattened FT snapshots already sent to the solver. The
duplicate direct-leaf scan was removed. Single and batch FT/ET paths share the fix.

For example, the first reconstructed LOOP sequence changed from
`0.9974030462117026` to approximately `0.9973947758160392`, matching the independent
BN. The change is in backend input adaptation; no solver algorithm changed.

## Numerical acceptance and precision limits

- Compact scalar and native probability checks use relative tolerance `2e-10`.
  Expected zero requires exact zero. Every positive reference requires a
  positive output, including regressions around `1e-15` and `1e-100`.
- Case-study noncoherent paths also allow absolute roundoff of four machine
  epsilons, with a simultaneous relative-error ceiling of **0.1%**. Annual
  sequence budgets scale with initiating frequency. Zero cannot pass for any
  positive reference. The observed maximum relative difference was about
  **0.051%**, for a probability near `1.6e-13`.
- This residual difference reflects floating-point complement subtraction in
  the source BDD calculation. These tests do not establish tighter relative
  accuracy for all rare noncoherent paths. Changing that algorithm requires
  a separate source/method review.
- UQ summaries require finite values and preserve positive means/bounds.
  Near-zero SD of a constant total such as success plus failure is judged
  against roundoff at the total's scale. Rust summary arithmetic still has
  bit-for-bit checks against unchanged HCL_MH/NumPy functions.

## Frozen references and provenance

`tests/hcl-reference-manifest.json` protects 27 input, output and generator
files. `tests/verify-hcl-references.mjs` verifies them, source metadata,
inter-fixture dependencies and copied XDSL inputs. Text hashes normalize CRLF
to LF for portable checkout verification; original source byte hashes remain
recorded. Deliberate artifact, generator, source and dependency corruption tests
must fail.

When `resources/HCL_MH` is present, all 15 referenced source files must match.
When absent, CI verifies the frozen artifacts and recorded provenance and
explicitly reports that the original checkout was not inspected. For a local
source review, require it:

```sh
node apps/solvers/praxis/tests/verify-hcl-references.mjs --require-sources
```

The five frozen XDSL inputs let frontend source/import tests run without a
local HCL_MH checkout. Their original source paths and hashes are retained.
The HCL_MH reference generators require their documented pinned Python/NumPy/
SciPy environment and the original source checkout. Regeneration and manifest
changes require review; tests never rewrite expected outputs.

## Reproducing the checks

From the repository root:

```sh
npm --prefix apps/solvers/praxis-node run build
npm --prefix apps/solvers/praxis-node test
cargo test --manifest-path apps/solvers/praxis/Cargo.toml
cargo test --manifest-path apps/solvers/tensorbayes/Cargo.toml
cargo test --manifest-path apps/solvers/praxis-node/Cargo.toml --lib
pnpm nx run-many -t test --projects=backends-web-backend,frontends-web-frontend,interfaces-shared-types
pnpm nx run praetor:test
```

Use separate Cargo target directories for separate manifests; sharing a target
between the standalone PRAXIS and addon builds can reuse incompatible dependency
artifacts. CI builds the addon before backend tests, runs native numerical and
reference checks, and includes shared contracts and TensorBayes tests.
